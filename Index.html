Project Sentinel

The Next-Generation Framework for Offensive Security Research, Penetration Testing, and Automated Cloud Vulnerability Auditing.

Introduction to Modern Threat Landscapes

In the rapidly evolving world of cybersecurity, the perimeter has dissolved. Traditional monolithic network architectures have been replaced by distributed cloud environments, highly decoupled microservices, and ephemeral containerized applications. This shift has brought unprecedented scalability and speed to software development, but it has also exponentially increased the attack surface. Security teams, both red (offensive) and blue (defensive), are struggling to keep pace with the velocity of modern CI/CD pipelines.

This is where Project Sentinel comes in. Built by security researchers for security researchers, Sentinel is not just another vulnerability scanner. It is a comprehensive, highly modular, and asynchronous auditing framework designed specifically to navigate the complexities of zero-trust networks, Kubernetes clusters, and multi-cloud environments. By mimicking the advanced persistent threats (APTs) of today, Sentinel allows organizations to proactively identify misconfigurations, logic flaws, and exposed credentials before malicious actors can exploit them.

Core Architecture & Design Philosophy

The core philosophy behind Project Sentinel is "Shift-Left, Act-Right." This means the tool is lightweight enough to be integrated directly into developer workflows, yet powerful enough to be the primary weapon in a seasoned penetration tester's arsenal during a live engagement.

Sentinel is built on a highly concurrent Python engine utilizing asyncio, allowing it to perform thousands of non-blocking I/O operations simultaneously. This makes it incredibly fast when mapping massive IP spaces or fuzzing hundreds of API endpoints. Furthermore, the architecture is entirely plugin-driven. Every scanning module, payload generator, and reporting formatter is decoupled from the core engine. This allows security engineers to easily write custom plugins in Python or Go to target proprietary internal services or newly discovered zero-day vulnerabilities without needing to recompile the entire framework.

The framework utilizes a graph database backend to dynamically map relationships between discovered assets. For example, if Sentinel discovers an exposed S3 bucket containing a hardcoded API key, the engine will map that key to the respective user, query the permissions of that user, and automatically pivot to test those permissions against other discovered internal services.

Comprehensive Feature Set

Project Sentinel ships with a robust library of built-in modules designed to tackle the most common and devastating vulnerabilities found in modern web applications and cloud infrastructure.

Heuristic-Based Asset Discovery

Unlike traditional port scanners that blindly throw packets at firewalls, Sentinel uses OSINT (Open Source Intelligence), DNS sub-domain brute-forcing, and certificate transparency logs to passively map an organization's external footprint. Once inside a network, it utilizes heuristic analysis to identify services based on banner grabbing and behavioral responses, rather than relying solely on default port numbers.

Advanced Authentication Bypass & JWT Forging

Modern applications heavily rely on JSON Web Tokens (JWTs) for session management. Sentinel includes a dedicated cryptographic module that automatically checks for common JWT misconfigurations. It attempts attacks such as algorithm confusion (changing RS256 to HS256), signature stripping, and brute-forcing weak HMAC secrets offline. If successful, Sentinel can forge administrative tokens to demonstrate maximum impact during a penetration test.

Server-Side Request Forgery (SSRF) Hunter

Cloud environments are particularly vulnerable to SSRF. Sentinel automatically injects custom out-of-band (OOB) DNS payloads into headers, parameters, and JSON bodies. If an application blindly fetches the injected URL, Sentinel catches the callback on its own listener infrastructure, confirming the vulnerability. It then automatically attempts to pivot to internal cloud metadata endpoints (like 169.254.169.254 for AWS) to exfiltrate IAM credentials.

Installation and Deployment

Getting started with Project Sentinel is designed to be frictionless. We recommend running Sentinel within a dedicated virtual environment or using our official Docker container to avoid dependency conflicts with your host operating system.

To install from source, you will need Python 3.10 or higher. Execute the following commands in your terminal:

# Clone the main repository
git clone https://github.com/project-sentinel/sentinel-core.git

# Navigate into the directory
cd sentinel-core

# Create a virtual environment
python3 -m venv venv
source venv/bin/activate

# Install the required dependencies
pip install -r requirements.txt

# Run the initial database migration and setup
python sentinel.py --setup

# Verify the installation
python sentinel.py --version

Once installed, you can begin your first scan by specifying a target domain and the modules you wish to load. For example, to run a lightweight, passive reconnaissance scan: python sentinel.py -t example.com -m recon/passive --format json.
